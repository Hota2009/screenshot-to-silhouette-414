## Service pages

Services use the existing TanStack Start SSR route `/services/$slug`. Language is
explicit in `?lang=en` or `?lang=ar`; switching language preserves the path, other
query parameters and fragment. The home page remains a single scrolling page.
All bilingual service copy is typed in `src/content/site.ts`. `ServicePage` shares
Navbar, Footer, Contact, Button, Reveal, typography primitives and ServiceCard.

Canonical URLs and hreflang use `VITE_SITE_URL` when configured, falling back to
the current public URL supplied for this project:
`https://screenshot-to-silhouette.ahmedhota2009.workers.dev`.
When changing the production domain, set `VITE_SITE_URL` before building.
Both `/robots.txt` and `/sitemap.xml` are generated by the existing server entry
from that domain; there is no separate hardcoded public robots file to maintain.
The sitemap includes both languages for the home page and all seven services.
Deploy the full TanStack/Cloudflare server output, not only the public assets, so
service URLs and refreshes continue to render through SSR.

## Search metadata and indexing

`src/content/site.ts` holds the typed bilingual SEO titles and descriptions.
`src/lib/seo.ts` produces server-rendered canonical/hreflang (including x-default),
Open Graph/Twitter previews, and JSON-LD for Organization, WebSite, WebPage,
Service and BreadcrumbList. Organization contacts come from the same records as
the visible contact section. No ratings, opening hours, addresses or certifications
are invented. Cover artwork is used for sharing; field photographs remain separate.

An explicit `lang` query is authoritative. A URL without a language renders English
on both server and client so the visible content cannot silently diverge from the
indexed metadata. The language switch retains the current path and fragment.
Tracking parameters are excluded from canonicals. Error responses retain their
HTTP error status and receive an `X-Robots-Tag: noindex, follow` header.

After `npm run build`, run `node scripts/check-seo.mjs --built` to audit the emitted
Worker across all 16 language/page combinations: metadata uniqueness, language,
canonical and alternate links, share-image files, structured data, robots, sitemap,
404 handling and tracking parameters. For the running development server use
`node scripts/check-seo.mjs` (or provide its origin as the first argument).

After deployment, verify the approved domain in Google Search Console, submit
`/sitemap.xml`, and inspect the home page and service URLs. Search Console access
and a public deployment are needed for this external validation; neither is claimed
by the local tests. Indexing, ranking gains and rich-result appearance are not guaranteed.

Implementation references: [localized pages](https://developers.google.com/search/docs/specialty/international/localized-versions),

[Organization](https://developers.google.com/search/docs/appearance/structured-data/organization),
